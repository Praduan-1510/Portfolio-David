Overview

What we're building, and the rules.

Frontend only. The FSD's server & sync concerns are represented by a mock data/sync layer so the prototype behaves like the real thing — loading, errors, permissions, paywalls, undo — without a production backend.

◑

Complete UI/UX

Every screen, modal, and state from the FSD — 106 screens, 170 sheets, ~355 states — built on one token-driven design system with light, dark & high-contrast themes.

⚡

Fully functional

A mock API with real latency & error injection, a permissions engine, an entitlements engine, optimistic updates + global undo, and URL-restorable state. It clicks, gates, and persists for real.

◇

The signature

The FSD flags its own gap (G-10 / Q-08: "no signature"). Already answered — the Day-Arc identity: warm→cool spectrum, arc/orb logo, gradient-forward surfaces. Locked before the component library.

🧭 Guiding rule (FSD §17): "Adjust durations, not order — the dependencies are real." Entitlement checks are built with the features they gate; audit logging is added with each module; and every screen ships with its empty, error, and permission states — never deferred.

Prototype Architecture

Why it's fully functional, not a mockup.

A mock data + sync layer stands in for the backend so every interaction — loading, errors, permissions, paywalls, undo, deep links — behaves for real.

Stack

  • React 18 + TypeScript + Vite
  • React Router — URL is the source of truth for view state
  • Motion (Framer) for animation
  • TanStack Table — virtualized data grid
  • Design tokens as CSS custom properties (Day-Arc)
  • Charts wired to the §8.14.1 categorical ramp

The mock "backend" — DATA-1

  • Seed factory — deterministic orgs, members, records, invoices
  • Mock API — in-memory, real latency + error injection
  • Optimistic updates + a global undo stack (G-06)
  • Permissions engine — the §20.1 role matrix
  • Entitlements engine — plan limits + usage metering
  • URL-state sync + refresh-safe persistence

Data entities mocked

  • Org · Workspace · Member · Role
  • Record · View · Comment · Activity
  • Notification · Subscription · Invoice · Usage
  • Entitlement · ApiKey · Webhook · AuditEvent
  • Org state machine: trialing→active→past_due→restricted→cancelled
  • Switchable in a demo panel to show every commercial state

Quality & Definition of Done

A screen isn't done until it's all done.

QA-1 gates every phase. No "we'll add the states later" — that's how a release slips (FSD §17).

Definition of Done — every screen

  • ✓ All applicable states (default → skeleton → error → empty → permission-denied)
  • ✓ Keyboard-operable end-to-end with visible focus
  • ✓ WCAG 2.2 AA — contrast, labels, roles, live regions
  • ✓ Responsive to 375px; modals become full-screen sheets <768px
  • ✓ Motion respects prefers-reduced-motion
  • ✓ Consumes semantic tokens only — no hard-coded hex/px
  • ✓ Mock-data happy path + at least one error path
  • ✓ Deep-link / URL state restores exactly
🔍 The one gap the mining flagged: "states" are the thin dimension (~190 enumerated vs ~355 target). Root cause — the universal-state matrix is defined once in the foundation but the official count multiplies it per screen. Remediation is built into Sprint 15: state-matrix-checker walks every screen and asserts its applicable universal states, reconciling 190 → ~355. M11 Settings and M5 get priority (largest gaps).

Risks & the Sprint-0 decisions (FSD §19.4)

G-10
Design signature — resolved. The Day-Arc identity (spectrum + arc/orb logo + gradient surfaces) answers Q-08. Locked before the component library — restyling 60+ components post-launch is a quarter of work.
G-02
Mock-sync contract. The optimistic-update + global-undo model is decided in Phase 0 — every data path depends on it, so it can't be retrofitted.
RBAC
Permissions & entitlements as data. Both engines land in Phase 0 so features gate consistently and checks are built with the features, never bolted on.
§11.1
Performance from day one. QA-1 enforces budgets from Phase 0 — virtualization beyond 100 rows, module-boundary code-splitting, ≤250KB initial route JS.
A-06
Billing is the highest-risk late change. M9 pricing/packaging is frozen before Phase 3; state completeness on dunning/restricted/declined paths is non-negotiable.
